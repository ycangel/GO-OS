# GO OS v0.5.0 Foundation Release Plan

**Chinese release name:** 奠基版本

**Status:** release planning record; the shipped scope is authoritative in
[Release Notes](RELEASE_NOTES_v0.5.0.md)

`Foundation Release` describes a software milestone. It does not announce or
imply a legal foundation or a legal entity named “GO Foundation.”

## Objective

Turn the exploratory v0.1–v0.4 sequence into one coherent public baseline for
building and falsifying self-evolving organizational systems.

The release should make five things clear:

1. the constitutional boundaries that implementations may not bypass;
2. the frozen core objects and their relationships;
3. which artifacts are current versus historical;
4. what is implemented, specified, demonstrated or still planned; and
5. how a reviewer can challenge the model and code.

## Core message

> **Reinvent Organizations.**
> **Enable organizations to evolve themselves.**

Supporting formula:

> **Human Sovereignty × Machine Agency × Reality as Final Arbiter**

## Release scope

### Included

- bilingual public narrative and release naming;
- canonical documentation index;
- v0.5 Architecture Overview and eight-object model;
- Quick Start around one bounded, reversible mission;
- whitepaper editorial structure and evidence obligations;
- release and migration records;
- schemas and release manifests;
- Skills and human-approval boundaries;
- declared evaluation and red-team cases;
- GO Society Web alpha reference surface;
- repository consistency and Web build checks.

### Not claimed

- a complete production runtime for all eight objects;
- autonomous AI governance;
- security, regulatory or safety certification;
- proven cross-vendor cognitive portability;
- proven organizational or commercial outcomes;
- the existence of a legal foundation.

## Definition of done

- repository release is consistently `0.5.0` where the repository release is
  intended;
- component and historical versions retain their own provenance;
- all canonical links resolve;
- machine-readable JSON and YAML structures pass the documented checks;
- Skills expose human authority, candidate-only AI output and escalation;
- Web package, build, migration and runtime claims align;
- Foundation Release is translated as “奠基版本” and no legal entity is
  implied;
- known limitations and unexecuted evaluations are visible;
- the next red-team checklist is ready;
- the default branch contains a reviewed, reproducible release commit.

## After the baseline

Do not measure progress by document count. The next gate is an independent
red-team review followed by one real, bounded mission with a baseline, explicit
authority, real action, counter-evidence, human decision and post-change
observation.
