# GO Society Operating Charter v0.1

**Status:** Founding / Public Alpha  
**Parent system:** GO OS  
**Form:** Human–Agent Cell evolving toward an open contributor network

## Identity

GO Society is the organization behind GO OS and the first living reference implementation of GO OS.

> **A self-evolving organization for self-evolving organizations.**

GO Society does not merely explain GO OS. It uses GO OS to run its own missions, constrain authority, observe reality, manage exceptions, retain evidence, develop capabilities and propose changes to itself.

Its operating history is part of the evidence for—or against—the GO OS thesis.

## Vision and mission

**Vision:** Reinvent Organizations.  
**Mission:** Enable organizations to evolve themselves.

GO Society advances that mission by:

1. Building and maintaining an open, deployable GO OS runtime.
2. Publishing field evidence, not only finished doctrine.
3. Growing an open network of builders, contributors and organizational pioneers.
4. Forming bounded design partnerships with organizations willing to rebuild themselves.
5. Turning verified learning into reusable skills, policies, adapters and capabilities.

## Constitutional invariants

GO Society inherits the GO OS Constitution. It may evolve its structure and methods, but it may not silently rewrite these invariants:

1. **Human Sovereignty** — named humans retain purpose, value judgment, irreversible commitment and final responsibility.
2. **Machine Agency** — systems and agents may plan, act, coordinate, verify and learn inside explicit authority.
3. **Reality Finality** — evidence from reality outranks plans, narratives, status and internal consensus.
4. **Named Accountability** — consequential missions and exceptions retain a named accountable human.
5. **Reversibility & Exit** — meaningful changes require a stop condition, rollback path or explicit irreversible decision.

No Agent may expand its own authority. No automated result removes human responsibility.

## Initial missions

### M-001 — Make GO OS runnable

Turn GO OS from a constitutional framework and skill system into usable, deployable web software.

**Success signal:** a real organization advances a recurring mission with lower coordination load and no loss of accountability, stoppability or learning quality.

### M-002 — Build the GO Society commons

Create a public field of code, skills, Field Notes, evidence and contributors that compounds the ability to reinvent organizations.

**Success signal:** external contributors reuse, challenge and improve GO capabilities through traceable evidence.

### M-003 — Find the first organizations ready to evolve

Reach decision-makers who want to rebuild their organizations and form bounded evidence-producing design partnerships.

**Success signal:** three qualified organizations enter a GO OS probe with explicit mission, authority, evidence, stop and learning conditions.

## Operating loop

GO Society operates through the following loop:

`Purpose → Mission → Authority → Action → Reality → Evidence → Learning → Adaptation`

Normal activity should remain quiet. Human attention is requested only when:

- authority is insufficient or ambiguous;
- evidence contradicts a consequential assumption;
- a value conflict or irreversible commitment appears;
- risk exceeds the approved operating boundary;
- a named human must accept responsibility for the next action.

The default management model is therefore **exception-driven governance**, not continuous approval.

## Public operating surfaces

- **GO OS** — the open-source constitutional framework, skills, schemas and runtime.
- **GO Society Web** — the working surface for Missions, Evidence, Exceptions, Capabilities and Evolution Missions.
- **GO Commons** — reusable skills, templates, policies and approved learning.
- **GO Field Notes** — public assumptions, evidence, contradictions, experiments and learning.
- **GO Network** — contributors, adopters and organizational pioneers.
- **GO Works** — a possible future commercial Domain Cell; not yet constituted.

## Evolution rules

Any member or authorized Agent may propose an Evolution Mission. A valid proposal must include:

1. the evidence showing why the current organization is insufficient;
2. the proposed change to structure, rule, capability or memory;
3. a named sponsor;
4. affected authority and responsibility;
5. success and failure signals;
6. reversibility, rollback and exit conditions;
7. the human decision required, if any.

Changes become organizational capability only after reality produces sufficient evidence. Repetition is not proof; a polished narrative is not evidence.

## Founding exception

GO Society must separate open ecosystem stewardship from confidential or commercial enterprise work. Before recurring commercial commitments begin, the Sovereign Founder must decide whether **GO Works** becomes a distinct Domain Cell and what evidence, rights, learning and data may cross that boundary.

## Founding test

GO Society succeeds only if running itself on GO OS creates measurable improvement:

- less human monitoring and coordination burden;
- faster movement from signal to responsible action;
- earlier detection of consequential deviation;
- clearer authority and named responsibility;
- more reusable organizational capability per cycle;
- visible ability to question and safely rewrite itself.

If the runtime adds ceremony without reducing attention load or improving reality alignment, GO Society must treat that result as evidence against its current design and evolve it.
