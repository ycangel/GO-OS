# GO OS — Godel Organization Operating System

**版本：** v0.1.0  
**状态：** Public Alpha

GO OS（Godel Organization，哥德尔组织）是一套面向 **AI 原生组织** 的开放框架与 Skills 系统。

它的基本判断是：未来企业不应只是“传统组织 + AI 工具”，而应成为一个由人赋予目的与责任、由机器获得大规模行动能力，并通过现实证据持续修正自身的组织智能系统。

> **Human Sovereignty × Machine Agency × Reality as Final Arbiter**  
> **人的主权 × 机器的行动权 × 现实拥有最终仲裁权**

GO OS 的核心运行回路：

`Purpose → Mission → Authority → Action → Reality → Evidence → Learning → Adaptation`

即：

`目的 → 使命 → 权限 → 行动 → 现实 → 证据 → 学习 → 适应`

## 为什么叫 GO？

**GO = Godel Organization（哥德尔组织）。**

这个名字取意于 Kurt Gödel。它在组织上的隐喻是：任何足够复杂的组织，都不应该假设一套固定规则能够永久解决未来出现的所有问题。真正具有生命力的组织必须能够观察现实、发现异常、质疑自己的规则、更新认知，并在必要时改写自身。

同时，**GO** 也是行动：出发、验证、学习、进化。

## GO OS 管理什么？

GO OS 不把 Task（任务）作为组织的第一对象，而把以下对象作为更底层的组织原语：

- **Mission / 使命**：必须产生什么结果，以及为什么。
- **Authority / 权限**：谁或什么 Agent 可以做什么决定、承诺什么资源。
- **State / 状态**：现实系统此刻处于什么状态。
- **Evidence / 证据**：什么事实支持、反驳或更新我们的判断。
- **Exception / 异常**：什么情况超出了原有假设、权限或正常运行边界。
- **Capability / 能力**：能够被复用、积累，并提高未来执行质量的能力。
- **Organizational Memory / 组织记忆**：被保留下来的决策、证据、模型、经验与模式。

## 七项设计承诺

1. **现实优先**：证据高于层级、话语权与模型自信。
2. **人的主权**：执行可以委托，责任不能消失。
3. **机器行动权**：能力足够的机器不应被不必要的逐项审批束缚。
4. **使命原生**：组织关注结果与状态变化，而不是活动数量。
5. **异常驱动人类注意力**：人把精力迁移到模糊、冲突、不可逆决策和新边界。
6. **学习优先**：一次执行不仅要完成事情，还要提高下一次执行的能力。
7. **自我改写**：组织不仅能改行动，还能改假设、规则、结构与 Skills。

## 版本规则

采用 Semantic Versioning：

- `MAJOR`：核心本体或行为发生不兼容改变。
- `MINOR`：增加新能力、新对象或重大框架扩展。
- `PATCH`：澄清、测试、示例及非破坏性改进。

当前版本：**v0.1.0**。
