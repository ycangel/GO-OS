# Intelligent Compounding & AI-Native Business v0.1.0

## Purpose

Determine whether AI creates a structural compounding advantage in a business and redesign the business so usage, evidence, intelligence, customer value and organizational capability reinforce one another.

## Use when

Use for AI-native business models, AI moats, data advantage, product loops, customer personalization, platform/network effects, questions about whether AI is merely a feature, or how a business can improve with use.

## Required inputs

- customer and problem;
- product / service;
- value creation process;
- data generated by use;
- AI capabilities involved;
- feedback mechanisms;
- switching / trust dynamics;
- cost structure;
- network participants if any.

## Core distinction

**AI-enhanced business:** AI lowers cost or improves a feature, but each transaction does not materially strengthen the system.

**AI-native compounding business:** each meaningful cycle generates evidence, capability or network value that improves future cycles.

## Compounding-loop library

### Data Loop
`usage → proprietary evidence → better understanding → better outcome → more usage`

### Capability Loop
`execution → exception → learning → reusable capability → higher-quality execution`

### Customer Loop
`better fit → better result → trust / retention → richer interaction → better fit`

### Distribution Loop
`better product → lower acquisition friction → more users → more learning → better product`

### Network Loop
`more participants → more interactions → better coordination → more participant value → more participants`

### Economics Loop
`automation / intelligence → lower marginal cost → broader viable demand → more usage → more learning → further cost / quality improvement`

## Procedure

### 1. Map the current value loop

Show how value is created from first customer contact to outcome.

### 2. Identify intelligence insertion points

For each step ask whether AI can improve:

- prediction;
- generation;
- matching;
- planning;
- execution;
- coordination;
- verification;
- personalization;
- learning.

### 3. Test for compounding

For each AI improvement ask:

- Does use generate unique evidence?
- Does that evidence improve future quality?
- Is improvement retained as memory or capability?
- Does improved quality increase usage, trust, retention or network value?
- Can competitors access the same improvement equally easily?

### 4. Find the weakest link

A loop breaks when data cannot be used, evidence is low quality, learning does not reach the product, users do not experience improvement, or benefits are fully commoditized.

### 5. Design proprietary learning

Prefer unique interaction, outcome and exception data over raw data volume.

### 6. Connect organizational learning to customer value

Internal learning is strategically useful only when it improves cost, speed, quality, reliability, experience or strategic optionality.

### 7. Check anti-compounding risks

Watch for:

- model commoditization;
- generic public data dependence;
- one-way automation with no feedback;
- low trust;
- regulatory barriers to reuse;
- local optimization that degrades customer value;
- runaway error loops.

## Decision rules

- Do not call a business AI-native simply because AI is central to the product.
- Proprietary evidence quality matters more than generic data volume.
- If every competitor can buy the same model and achieve the same result, the moat is elsewhere.
- Strong businesses compound customer value and capability, not only automation savings.

## Output contract

Return:

- AI-enhanced vs AI-native judgment;
- current loop map;
- compounding loops present;
- broken links;
- proprietary evidence opportunities;
- capability loops;
- moat durability assessment;
- risks of commoditization;
- next experiments and success evidence.

## Failure / escalation conditions

If claims about data advantage cannot be verified, label them as hypotheses rather than moats.

## Evaluation prompts

- “We replaced customer support with a chatbot. Are we AI-native?”
- “Find the compounding loops in our marketplace.”
- “How can a company keep an advantage when foundation models commoditize?”
